## Overview

image::chboot-part-roller.svg[]

This plugin for lliurex-chboot provides functionality to restore (and save) system partition using partclone and a compressed image file.

The program works in much the same way as the save/restore partition options in clonezilla, but in a fully automated manner. In addition, chboot-partition-roller also reinstalls GRUB and preserves some essential settings and files from the original system to ensure the computer works properly after the image has been installed. Any differences in partition name or size between the image and the installation destination are also handled automatically.

Partition roller (aka part-roller) uses configuration files (see section 'Configuration' below) to generate chboot entries to provide alternative boot methods that allow to use a partclone image file to restore or save the operating system partition. It can manage different configuration files to provide multiple boot alternatives.

The intended use is to simplify and automate the upgrade between major versions of the operating system using an image created from an installation of the new version of the system.

## How it works

The software generates a custom initrd file (using the actual running kernel) including the partclone binary, disk and compression tools, and required init scripts. All the necessary tools to restore (or create) a system image are installed in the ramdisk, so no root partition filesystem is needed for the boot process, but disk storage is needed to store the image file (and some additional data). As alternative, in a LAN environment, the image can can be accessed from an HTTP server and written directly to the target partition without the need of intermediate storage.

Partition roller is a generic tool to handle partclone images but it does not provide any specific image file by itself. The package includes a main script 'chb-part-roller' for the "low-level" operation but provides also the required hooks to integrate with lliurex-chboot tool. A configuration file must be provided to specify the image file to be used, along with other options to be able to operate part-roller in chboot context. Some examples of configurations for different scenarios are included in the package.

The image file can be generated using the software itself (recommended way), but (almost) any partition image file created with partclone can be used, including existing backup images generated with clonezilla, although you should avoid using different versions of partclone to save and restore the image. In particular, to simplify the installation of LliureX 25, the package 'lliurex25-OEM-part-roller' can be used to download (or copy) a generic LliureX 25 image to upgrade isystems from LliureX 23 OEM instalation.

## Saved files and settings from original system

part-roller preserves and prepares some date from actual system before an image file is restored. This include (some) user and group credentials and essential files.

This data is copied to the chboot partition BEFORE booting into recovery mode when part-roller is used with the chboot command 'chbootmgr prepare'.

This feature provides 2 advantages:

 - Continue with image restore in the event that the process is interrupted due to a power cut or any other incident
 - Automate and minimise manual configuration of the new system, whilst retaining the essential settings of the previous OS.

## Operation

The main script 'chb-part-roller' can be used as follows:

```
Usage: chb-part-roller {mkinitrd|gengrub|saveusers|savefiles|installgrub} CFG_NAME
```

But the intended use of partition roller is via chbootmgr tool, so in most cases, it will not be necessary to run this script directly.

To use part-roller with chboot, the first step is to write a configuration file with '.cfg' extension (see next section 'Configuration') in directory:

'/etc/chboot-part-roller/conf.d'


Once you have the file, let’s say '/etc/chboot-part-roller/conf.d/**{CFG_NAME}**.cfg'

you must run the following commands:


### Install files

This is a mandatory action to be able to use part-roller.

You must run this command at least one time for each configuration file in order to create the required directory structure under /chboot/liurex-chboot/srcs/{CFG_NAME} :

```
chbootmgr install part-roller {CFG_NAME}
```

Please note that this is the only 'chbootmgr' instruction in which the “part-roller” parameter needs to be used.

**In advance, only the {CFG_NAME} needs to be included in commands.**

### Prepare the {CFG_NAME} chboot entry

By default, all the required data to generate the chboot {CFG_NAME} entry is read from configuration file, but you can include some optional parameters to change this behaviour.

The optional parameters are used to configure entry but are not saved in the configuration file

```
chbootmgr prepare {CFG_NAME} [optional parameters ...]

Optional parameters available:

  General options

--force : disable interactive prompt

  Alternative image options

--override-image : Ignore existing image file and download or copy again the file.
--copy-image {IMG FILE PATH} : provides an existing file path to copy the image file
--download-image {IMG URL} : provides an alternative URL to download the image file from
(Note: the previous commands can be used as an alternative source for the image file, but 
       the image filename under /chboot/lliurex-chboot/imgs is not changed)

```

This command creates the required directory structure under /chboot/liurex-chboot/srcs/{CFG_FILENAME}

### Remove the {CFG_NAME} image and data files

To liberate disk space without unistalling entry, you can run the command:

```
chbootmgr free-up {CFG_NAME}
```

This command reverses the 'prepare' command as described above.

### Uninstall the {CFG_NAME} chboot entry


```
chbootmgr unistall {CFG_NAME}
```

Running this command implies to execute also the previous command 'free-up'


## Configuration

Partition roller search for configuration files in directory /etc/chboot-part-roller/conf.d . At this stage, the files are actually fragments of shell scripts containing variables, which are sourced from the main script 'chb-part-roller', the file extension must be '.cfg'. A sample file 'part-roller-example.conf.DISABLED' is provided with the package.

### Configurable parameters by category:

#### General

```

PR_CHBOOT_MODE      -> Set chboot operation mode to RESTORE from file or URL or to SAVE to file
                       Valid options are:
                       'restore-from-file', 'restore-from-url' and 'save-to-file'
                       Default value is 'restore-from-file'

PR_GRUB_ENTRYNAME   -> Title to show in grub chboot entry.
                       Default value is:
                       PR_GRUB_ENTRYNAME="CHBOOT ${CFG_NAME} ${PR_CHBOOT_MODE} (${PR_IMAGE_FILENAME})"

```

#### Image file

```

PR_IMAGE_FILENAME   -> name of the 'target' image file (without path).
                       This is a mandatory setting, so no actions can be performed if empty.

PR_IMG_DOWNLOAD_URL -> URL for downloading the image (optional)

PR_DIRECT_URL_IMG   -> image file URL to restore partition from network (optional).
                       Leave it blank to disable direct network restore feature.

```

#### Saved files


```

PR_SAVEFILES_LIST   -> list of files in destination directory to be 'saved' and restored
                       after writting the image. It must contain the full path of a file.
                       Each line of the file is the full path of a file to store from the
                       previous system before the installation of the new image.
                       Wildcard characters and regular expressions are not currently supported.
                       The default value for this parameter is
                       '/usr/share/chboot-partition-roller/saved-files.list'.
                       The files '/etc/fstab' and LliureX tags from
                       '/etc/lliurex-auto-upgrade/tags/' are also automatically appended to the
                       list (tags with dots in the name are ignored).
                       Non existing files are silently ignored.

```

#### Saved users

```

PR_SAVEUSERS_MODE   -> At this moment, the only allowed value is 'saved-users'.
                       In this mode, local non system groups and user accounts are SAVED
                       before writting the image.
                       The stored data include all the fields of the /etc/passwd and /etc/group
                       files (including current numeric values for UIDs and GIDs).
                       Encrypted passwords and account expiry information from /etc/shadow and
                       /etc/gshadow is also stored.
                       After restoring the image, ALL local non system groups and user accounts
                       from the image file are DELETED and replaced with local users and groups
                       saved from the old pre-existent system.
                       System users and groups are usually managed by installed packages, so
                       they are not altered, they remain exactly as they appear in the image
                       file. However, local users’ membership of system groups is restored from
                       the previous system, but only for those system groups that exist in the
                       new image.
                       If the variable 'PR_SAVEUSERS_MODE' is empty or has any other value,
                       the user and group information from the old system will not be retained
                       and the accounts from the image will not be modified.

PR_USERS_BLACKLIST  -> Blank separated list of local users to be excluded from save/restore
                       Default value is:
                       PR_USER_BLACKLIST="estudiant nobody guest-user"

PR_GROUP_BLACKLIST  -> Blank separated list of local groups to be excluded from save/restore
                       Default value is empty.

PR_SYS_USERS_LIST   -> Special system users list. For this users, '/etc/shadow' data is saved
                       from original system and restored after image installation.
                       Default value is:
                       PR_SYS_USERS_LIST="root"

```
